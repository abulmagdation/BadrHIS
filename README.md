# BadrHIS — بدر لإدارة المرضى

React + Vite + Node.js + MongoDB. يعمل محليًا أو داخل Docker وعلى Google Cloud Run. خط Cairo محفوظ داخل المشروع ويعمل بدون اتصال بالإنترنت.

**النشر السحابي ومتغيرات البيئة:** راجع [دليل Cloud Run](docs/CLOUD_RUN.md). ملف `Dockerfile` يبني الواجهة ويشغّلها مع API في حاوية واحدة؛ لا يحتوي أي بيانات مرضى أو إعدادات اتصال سرية.

## التشغيل

يتطلب Node.js 22.13 أو أحدث وخدمة MongoDB محلية تعمل على `127.0.0.1:27017`.

```powershell
cd D:\BadrHIS
npm install
npm run build
npm start
```

افتح http://127.0.0.1:3000. للتشغيل اليومي افتح `start.bat` واترك النافذة مفتوحة. للتطوير: `npm run dev`. أوقف التشغيل بـ Ctrl+C قبل تشغيل نسخة أخرى.

## تسجيل الدخول والصلاحيات

- عند فتح النظام لأول مرة تظهر شاشة إنشاء حساب المدير الأول. لا توجد كلمة مرور افتراضية؛ اختر اسم المستخدم وكلمة المرور بنفسك، وكلمة المرور يجب ألا تقل عن 8 أحرف.
- بعد إنشاء المدير تصبح كل صفحات وواجهات البيانات محمية بتسجيل الدخول. الجلسة محلية بملف Cookie محمي، وكلمات المرور محفوظة بتشفير اشتقاقي `scrypt` ولا تُحفظ كنص صريح.
- المدير يرى صفحتي «المستخدمون» و«سجل النشاط». يمكنه إضافة مديرين أو مستخدمين عاديين وتعطيل الحسابات وإعادة تفعيلها. المستخدم العادي يصل إلى العمل اليومي ولا يستطيع إدارة الحسابات أو قراءة سجل النشاط.
- إضافة الأقسام وتعديلها وحذفها متاحة للمدير فقط. المستخدم العادي يرى الأقسام وسعتها وأعداد المرضى ويستطيع عرض المرضى المسكنين فيها دون تغيير بيانات القسم.
- كل عملية إنشاء أو تعديل أو نقل أو خروج أو حذف مؤقت أو استعادة تُسجل باسم المستخدم ووقت التنفيذ ووصف العملية.
- حذف المرضى والأقسام وتعطيل المستخدمين حذف مؤقت. تبقى السجلات محفوظة، ويمكن للمدير استعادة المرضى والأقسام من «سجل النشاط والمحذوفات» وإعادة تفعيل المستخدم من صفحة المستخدمين.

## الأرقام الطبية والزيارات

- اترك الرقم الطبي فارغًا لإنشائه تلقائيًا. يبحث النظام عن أكبر رقم طبي رقمي موجود بصيغة `BADR12345` (ويحسب الأرقام الصريحة أيضًا) ثم يضيف 1؛ فبعد `BADR65490` ينشئ `BADR65491`. يمكنك أيضًا إدخال رقم يدوي (حتى 16 حرفًا إنجليزيًا/رقمًا/شرطة لتناسب الباركود). تُوحّد الحروف إلى الكبيرة وتتحول الأرقام العربية إلى الإنجليزية، مع الحفاظ على الأصفار البادئة.
- الرقم اليدوي الجديد ينشئ ملفًا جديدًا. الرقم الموجود يعرض هوية المريض تلقائيًا؛ إن كان خرج سابقًا، اختر القسم والسرير وأكّد الحفظ لإضافة زيارة جديدة بنفس الملف والباركود. لا تُستبدل الزيارات السابقة.
- إذا لم تتذكر الرقم الطبي، أدخل الرقم القومي في نموذج الدخول. يبحث النظام عن الملف المسجل ويعرض اسم المريض ورقمه الطبي لتختاره وتعيد دخوله مع الاحتفاظ بكل زياراته السابقة.
- المريض المقيم بالفعل لا يمكن إعادة إدخاله؛ استخدم النقل أو سجّل خروجه أولًا.
- الرقم القومي اختياري، وعند إدخاله يجب أن يكون 14 رقمًا ولا يتكرر بين ملفين. هذا تحقق شكلي، وليس تحققًا حكوميًا من هوية الرقم.
- عند كتابة رقم قومي مصري صحيح من 14 رقمًا يستخرج النظام تاريخ الميلاد تلقائيًا من خانات القرن والسنة والشهر واليوم. تظل خانة تاريخ الميلاد قابلة للكتابة والتعديل اليدوي، ويمكن الرجوع للتاريخ المستخرج بضغطة واحدة.
- الاسم الإنجليزي يتولد تلقائيًا ككتابة صوتية لأول ثلاثة أسماء عربية، مثل «محب أحمد علي محمد» ← `Moheb Ahmed Ali`. لا يترجم معنى الاسم، ويمكن تعديل التهجئة الإنجليزية يدويًا قبل الحفظ.
- اسم المريض وتاريخ الميلاد والهوية الموجودة لا تتغير أثناء إعادة الدخول. يمكن استكمال الرقم القومي إن لم يكن مسجلًا.
- البحث متاح بالاسم والرقم الطبي والرقم القومي والهاتف. الضغط على اسم المريض يعرض الزيارات وتواريخ الدخول والخروج وسجل الحركة.

## تعديل المرضى والأقسام

- زر القلم في صف المريض، وزر «تعديل بيانات المريض» داخل ملفه، يسمحان بتعديل الرقم الطبي والقومي والاسم وتاريخ الميلاد والنوع والهاتف. يمنع النظام تكرار الرقم الطبي أو القومي، ويسجل الحقول التي تغيرت في سجل الحركة.
- زر «تعديل» في بطاقة كل قسم يسمح بتغيير اسمه العربي والإنجليزي وسعته. لا يسمح النظام بتكرار اسم قسم أو خفض السعة عن عدد المرضى المقيمين فيه.
- تغيير القسم أو السرير يتم من زر النقل، حتى تظل حركة المريض بين الأقسام محفوظة في السجل.
- أعلى سجل المرضى يظهر اختيار مباشر للأقسام. الرقم على كل قسم يتبع الفلتر الحالي: عدد المقيمين عند عرض المقيمين، أو عدد حالات الخروج خلال آخر 24 ساعة عند عرض الخروج. اختيار القسم يعرض حالاته مباشرة.
- فلترة سجل المرضى تحتوي على «المقيمون» و«الخروج آخر 24 ساعة». حالات الخروج الأقدم تبقى محفوظة في ملف المريض وقاعدة البيانات، لكنها لا تظهر في قائمة الخروج اليومية. كارت الخروج العلوي يعرض عدد حالات آخر 24 ساعة فقط.
- يبدأ جدول سجل المرضى بأحدث 30 حالة، ثم يعرض 30 حالة إضافية تلقائيًا عند الوصول إلى أسفل القائمة. يتصفّر العدد عند تغيير القسم أو الحالة أو البحث.

## سجلات المرضى والتحميل التدريجي

- صفحة «السجلات» متاحة للمدير والمستخدم العادي، وتعرض كل ملفات المرضى غير المحذوفة، سواء كان المريض مقيمًا أو خرج منذ فترة.
- تعرض الصفحة أحدث 30 ملفًا أولًا، ثم تحمّل 30 ملفًا إضافيًا تلقائيًا عند الوصول إلى أسفل الصفحة. لا تُحمّل الواجهة كل السجلات القديمة عند فتح النظام.
- البحث يتم من MongoDB بالرقم الطبي أو الرقم القومي، ويمكن فتح ملف المريض الناتج لرؤية بياناته وكل زياراته وسجل حركته.
- سجل نشاط المدير يعرض أحدث 30 عملية، ويحمّل 30 عملية إضافية عند النزول داخل الجدول.

## قاعدة البيانات

القاعدة المستخدمة هي `badr_his_local` على MongoDB المحلي، ويخزّن كل ملف زياراته وأحداثه في وثيقة واحدة حتى تُحفظ عملية الدخول أو النقل أو الخروج مع تاريخها بشكل ذري. توجد فهارس فريدة للأرقام الطبية والقومية والأسرّة المشغولة وخانات سعة الأقسام.

يمكن نسخ `.env.example` إلى `.env` لتعديل المنفذ أو اسم القاعدة محليًا. يدعم `MONGODB_URI` اتصالًا محليًا أو خارجيًا بصيغتي `mongodb://` و`mongodb+srv://`. إعدادات الإنتاج موضحة في `.env.production.example` و[دليل Cloud Run](docs/CLOUD_RUN.md).

تم ترحيل بيانات SQLite القديمة مع الحفاظ على الأرقام والبيانات وسجل الحركة. الملف `data/hospital.sqlite` ومرافِقاته بقيت دون حذف كنسخة قديمة، وليست قاعدة التشغيل الحالية. سكربت `node server/migrate.js` ينفذ الترحيل مرة واحدة ويرفض الدمج داخل قاعدة أخرى غير فارغة.

لنسخة احتياطية من البيانات الحالية، استخدم MongoDB Database Tools بعد إيقاف التطبيق لمنع الكتابة أثناء النسخ:

```powershell
mongodump --uri="mongodb://127.0.0.1:27017" --db=badr_his_local --out="D:\BadrHIS\backups"
```

نسخ مجلد `data` وحده لم يعد ينسخ بيانات MongoDB الحالية.

## الباركود

ملصق **50 × 30 mm** بنوع CODE128 يحتوي الرقم الطبي الفعلي، سواء كان تلقائيًا أو يدويًا. يظل الرقم ثابتًا عند إعادة الدخول ويظهر القسم الحالي. للطباعة: مقياس 100%، ورق 50 × 30 مم، هوامش صفر، وتعطيل الرؤوس والتذييلات. جرّب المحاذاة على طابعتك.

عند اختيار قسم من صفحة المرضى المقيمين يظهر زر «تنزيل كل الباركودات». ينزّل النظام ملف ZIP واحدًا يحتوي ملف PDF مستقلًا بمقاس 50 × 30 مم لكل مريض مقيم في القسم، ويكون اسم كل PDF هو الرقم الطبي للمريض. تُنشأ ملفات PDF بدقة طباعة عالية تعادل 1200 DPI، كما يتوفر زر لتنزيل PDF عالي الجودة للحالة الواحدة من شاشة الباركود. لا تؤثر خانة البحث على التنزيل الجماعي؛ الملف يشمل كل المقيمين في القسم المختار.

## الاختبارات

`npm test` ينشئ قاعدة MongoDB مؤقتة مستقلة ثم ينظفها. يغطي الرقم القومي، التوليد التلقائي، الإدخال اليدوي، إعادة الدخول، الزيارات السابقة، منع التكرار، النقل والخروج، تعارض حجز الأسرّة وحفظ البيانات. `node tests/preview.js` يشغل قاعدة واجهة تجريبية منفصلة على المنفذ 3001.
